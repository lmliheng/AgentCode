# Spec Delta

## Purpose

定义模型与运行时之间的工具调用协议：向模型声明可用工具、把模型的原生工具调用翻译为运行时决策、并确立「无工具调用即完成」的终止语义。

## ADDED Requirements

### Requirement: 请求中声明可用工具

系统 SHALL 在每次模型请求中下发当前可用工具的声明，包含工具名称、描述与参数 JSON Schema。工具声明 MUST 来源于运行时实际注册的工具集合，MUST NOT 依赖在提示文本中描述工具或要求模型自行输出工具调用格式。

#### Scenario: 工具声明随请求下发

- **WHEN** 运行时注册了若干工具并请求模型决策
- **THEN** 该请求包含这些工具的名称、描述与参数 JSON Schema

#### Scenario: 无工具时请求仍然有效

- **WHEN** 运行时未注册任何工具
- **THEN** 请求仍然可发送，且不包含工具声明字段

### Requirement: 原生工具调用翻译为运行时决策

系统 SHALL 在 Provider 边界把模型响应翻译为运行时内部的决策表示，运行时内部决策表示 MUST NOT 依赖该翻译实现。翻译规则 MUST 为：单个工具调用对应一次动作决策；多个工具调用对应一次批量动作决策；无工具调用对应一次完成决策。

#### Scenario: 单个工具调用翻译为动作决策

- **WHEN** 模型响应包含一个工具调用
- **THEN** 运行时收到一次动作决策，其工具名与参数来自该调用

#### Scenario: 多个工具调用翻译为批量动作决策

- **WHEN** 模型响应包含多个工具调用
- **THEN** 运行时收到一次批量动作决策，其动作列表覆盖全部工具调用且顺序与响应一致

#### Scenario: 无工具调用回落为完成决策

- **WHEN** 模型响应不包含任何工具调用
- **THEN** 运行时收到一次完成决策，其内容来自该响应的文本

#### Scenario: 工具参数不可解析时产生失败观察

- **WHEN** 模型返回的工具调用参数无法解析为合法对象
- **THEN** 运行时记录一次失败的观察结果并继续循环，使模型有机会修正，而不是中断整个运行

### Requirement: 终止语义不依赖专门的终止工具

任务的完成 MUST 由「本轮没有工具调用」表达。系统 MUST NOT 为此引入专门的终止工具，也 MUST NOT 要求模型输出特定格式的文本来宣告完成。

#### Scenario: 无工具调用终结循环

- **WHEN** 模型某一轮未调用任何工具
- **THEN** 循环以任务完成停止，该轮文本作为最终答复

### Requirement: 控制流通过工具表达

对于需要模型主动触发的状态迁移，系统 SHALL 以工具形式提供入口。系统 SHALL 至少提供重新规划入口，使模型能提交新的步骤列表；SHALL 提供批量动作入口，使一次工具调用能携带多个待执行动作。

#### Scenario: 模型主动请求重新规划

- **WHEN** 模型调用重新规划工具并提供新的步骤列表
- **THEN** 运行时更新计划、递增计划版本号，并继续循环

#### Scenario: 模型通过批量入口提交多个动作

- **WHEN** 模型调用批量动作入口并携带多个动作
- **THEN** 运行时按配置的并发上限执行这些动作，并为每个动作记录独立的观察结果

### Requirement: 决策不以自由文本中的 JSON 为来源

系统 MUST NOT 从模型自由文本中提取 JSON 来作为决策来源。模型返回的普通文本 MUST 只作为完成时的答复内容。

#### Scenario: 非 JSON 文本不被解析为决策

- **WHEN** 模型返回一段包含花括号的普通说明文本且未调用工具
- **THEN** 运行时将其视为完成决策的答复内容，不尝试从中解析动作或重新规划

#### Scenario: 参数解析失败产生可读错误

- **WHEN** 工具调用参数解析失败
- **THEN** 观察结果中包含原始调用内容与失败原因，便于模型在下一轮修正
