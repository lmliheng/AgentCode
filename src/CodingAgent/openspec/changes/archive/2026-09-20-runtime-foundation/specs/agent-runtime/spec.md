# Spec Delta

## Purpose

定义 Agent 运行时的对话历史契约与运行状态可观测量：以真实消息序列（而非文本回放）构造每次模型请求，保证工具调用与工具结果在消息序列中始终配对合法，并累计模型返回的 token 用量。

## ADDED Requirements

### Requirement: 对话历史以真实消息序列维护

运行时的每次模型请求 SHALL 由结构化消息序列构成，其中助手消息的工具调用与对应的工具结果消息 MUST 成对出现且共享同一调用标识。系统 MUST NOT 以「把历史决策序列化为文本再回放到消息内容中」的方式构造历史。

#### Scenario: 工具调用与其结果成对

- **WHEN** 一次决策产生了工具调用并得到结果
- **THEN** 下一轮请求中该助手消息携带工具调用，紧随其后的工具结果消息通过调用标识与之关联

#### Scenario: 清理孤儿工具调用

- **WHEN** 消息序列中存在携带工具调用、但没有对应结果的助手消息
- **THEN** 构造请求时该工具调用被移除，序列中不残留无结果的调用

#### Scenario: 多轮交替结构保持有效

- **WHEN** 一个任务连续产生多次工具调用与结果
- **THEN** 消息序列保持「助手调用 → 工具结果」的交替结构，不出现结果先于调用或多次结果对应同一次调用

### Requirement: 决策记录可重建为可提交的消息序列

运行时 MUST 能从自身记录的决策与观察重建可提交的消息序列，使模型能观察到它此前每一次工具调用的真实结果。

#### Scenario: 从决策记录重建历史

- **WHEN** 运行时已记录若干次决策与观察，需要发起下一轮请求
- **THEN** 重建出的消息序列覆盖这些决策与观察，且工具结果的内容来自实际观察而非模型复述

#### Scenario: 初始轮次无历史

- **WHEN** 任务刚开始，尚无任何决策与观察
- **THEN** 重建出的消息序列由系统指令与任务目标构成，不包含空的工具调用或结果消息

### Requirement: 模型用量记录为可观测量

运行时 SHALL 累计每轮模型返回的 token 用量，并使其作为运行状态的一部分对外可读。用量缺失时 MUST 标记为未知，MUST NOT 以 0 或任何具体数值代替。

#### Scenario: 累计消耗随轮次增长

- **WHEN** 一次运行经历了多轮模型调用，且每轮都返回用量
- **THEN** 运行状态中的累计消耗等于各轮用量之和，且随轮次单调不减

#### Scenario: 缺失用量被标记为未知

- **WHEN** 某一轮模型响应未携带用量信息
- **THEN** 该轮不计入累计值，且运行状态明确表示用量不完整，而不是补 0

#### Scenario: 交互层读取到真实用量

- **WHEN** 运行结束后交互层展示 token 统计
- **THEN** 展示值来自运行状态中实际记录的用量，而非恒为 0
