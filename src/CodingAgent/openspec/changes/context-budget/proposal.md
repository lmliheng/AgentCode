# Proposal

## Why

`CodingAgent` 的 12 个工具各自设了输出上限，但那些上限是按**「防护网络 / 磁盘」**的口径定的，不是按**「上下文预算」**的口径定的。两个后果已经在代码里：

- `fetch_url` 的 `MAX_BODY_SIZE` 是 512KB —— 对 HTTP 请求是合理防护，折算成 token 约 128K，对上下文预算是灾难；一次抓取就可能吃掉整个窗口的一大块。
- `run_command` **没有任何上限** —— 一次 `npm test` 的失败输出可达数万字符，且失败摘要在**尾部**，简单头部截断会把最该看的信息切掉。

同时，**无法判断当前上下文有多大**。模型每轮都重发完整历史，所以输入成本随轮次平方增长；而 `AgentRunState` 既不记累计消耗，也不记「当前上下文大小」。地基 change `runtime-foundation` 已补上累计消耗（那是修缺陷），但预算口径的度量仍缺。

在上下文窗口为 1M 量级的模型上（DeepSeek 价格页对 `deepseek-flash` 标注 `CONTEXT LENGTH: 1M`，实际生效窗口待确认），**容量不是最紧的约束，成本与效果才是**。因此本 change 的目标是：把工具输出体量收进统一口径，并让上下文大小可度量 —— 但**不触发任何压缩行为**，压缩与硬闸留到窗口确认后再定。

## What Changes

**1. 工具输出预算统一口径**

- 引入统一的截断语义，替换目前三种混用的口径（字符 / 行数 / 条目数）：
  - **双重上限**：字符数与行数同时生效，避免「很多短行」绕过字符上限（如 `find /`、`ls -R`）。
  - **保头保尾**：同时保留输出开头与结尾，因为命令执行的失败摘要通常出现在尾部。
  - **外部化而非丢弃**：完整输出落盘保留，模型拿到「截断内容 + 文件路径」，需要时可再读回。
  - **幂等**：已截断的内容不再二次截断。
- 采用**两级兜底**：工具内部可按自身语义截断（知道该保什么），运行时层统一兜底（防止工具漏配）；工具级预算可覆盖全局默认。
- 修正失控项：`fetch_url` 的 512KB 口径收回到预算口径（**BREAKING**：单次抓取返回的正文长度会显著变小）；`run_command` 补上上限。
- 落盘位置放在工作区之外的临时目录，避免被误提交进版本库。

**2. 上下文大小可度量**

- 新增「当前上下文大小」度量，取最近一轮请求的实际输入 token 数，与已在 `runtime-foundation` 中补上的「累计消耗」分开存放。
- 两类口径 MUST 分开，不得合并为单一数字：累计消耗随轮次线性增长，而每轮重发全历史使当前上下文大小与累计值相差数倍，混用会导致严重误判。
- 度量 MUST 标注来源是实测还是估算；缺失时标记为未知。

**3. 预算判据来源明确**

- 明确预算判据（阈值）的来源与配置方式，使后续的压缩与硬闸有据可依。
- 本 change **不触发**任何压缩或截断历史的行为，也不改变循环的停止条件。

## Capabilities

### New Capabilities

- `tool-output-budget`: 工具输出体量的统一口径 —— 双重上限、保头保尾、外部化落盘、幂等、两级兜底
- `context-metrics`: 上下文大小的度量 —— 两类 token 口径分离、实测与估算标注、预算判据来源

### Modified Capabilities

无。`agent-runtime` 由 `runtime-foundation` 新建，尚未归档；本 change 不修改它，避免两个 change 同时创建同一能力。

## Non-Goals

本 change 明确不涉及：

- 历史压缩与摘要策略（T4）—— 不裁剪、不摘要、不丢弃历史
- 上下文超限的硬闸与停止行为（T5）—— 不改变停止条件
- 记忆的短期 / 长期 / 存储设计（Phase 2）—— 工具输出落盘只是溢出区，不是记忆设计
- 沙盒与执行隔离（Phase 3）
- MCP client 适配层（Phase 4）
- CLI 无头模式（Phase 5）
- `runtime-foundation` 已覆盖的内容：真实消息序列构造、Provider 边界翻译、审批链接线、独立复验、累计消耗

## Impact

- **代码**：`src/types/Tool.ts`（工具可选地声明输出预算）、`src/runtime/agent.runtime.ts`（运行时层兜底与度量记录）、`src/tools/` 下的 12 个工具（截断口径统一，`fetch_url` 与 `run_command` 为实质改动）、`src/tools/index.ts`
- **接口**：工具输出的结构会新增「是否被截断 / 完整输出所在路径」一类信息，使用工具结果的调用方需适配
- **依赖**：无新增（落盘使用 Node 内置能力）
- **破坏性**：`fetch_url` 单次返回的正文长度显著变小；依赖完整正文长度或依赖未截断命令输出的行为需调整
- **前置依赖**：本 change 的实现依赖 `runtime-foundation` 已落地（消息装配的接缝与运行状态字段），因为它修改的是同一段代码。两者应先后应用，不宜并行开发
